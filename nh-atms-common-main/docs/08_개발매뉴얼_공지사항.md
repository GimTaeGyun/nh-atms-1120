# 08. 개발 매뉴얼 — '공지사항'으로 보는 화면 하나 만드는 순서

> 처음 온 사람이 **화면 하나가 DB → 백엔드 → 프론트로 어떻게 이어지는지** 를 '공지사항' 견본으로 따라가 보는 문서입니다.
> 간단판입니다(4장 프론트만 자세히). 자세한 규칙은 각 단계 끝의 "더 보기" 문서를 봅니다.
> 실행·빌드·배포는 이 문서에서 다루지 않습니다 → [`01_실행_배포.md`](01_실행_배포.md).

## 0. 한눈에 보기

```
[브라우저] NoticePage.tsx  ──(조회 버튼)──▶  noticeApi.list()  ──GET /api/web/notice──▶
[백엔드]   NoticeController ─▶ NoticeService ─▶ NoticeMapper(.java/.xml) ──SQL──▶ [DB] TB_NOTICE
           ◀── ApiResponse{ data: PageResult<Notice> } ── (표에 그림)
```

| 계층 | 파일 (공지사항 기준) | 하는 일 |
|---|---|---|
| DB | `db/ddl/TB_NOTICE.sql`(참고), 개발 DB 의 `TB_SCR_MENU`·`TB_SCR_AUTH_MENU` 행 | 테이블, 메뉴·권한 |
| 계약 | `docs/07_API_계약.md` §3 | 주소·요청·응답 모양·권한·문구 코드 (정본) |
| 백엔드 | `atms-web/.../web/notice/{controller,service,mapper,dto}` + `resources/mapper/notice/NoticeMapper.xml` | API → 업무 규칙 → SQL |
| 프론트 | `domain/notice.ts` → `api/endpoints/notice.ts` → `screens/sample/NoticePage.tsx`(+ `NoticeParts.tsx`, `popup/Notice*Modal.tsx`) | 타입 → API 호출 → 화면 |
| 등록 | `screens/screenIds.ts`, `screens/registry.ts` | 화면키 `sample.notice` ↔ 경로 `/sample/notice` |

(백엔드 경로 앞부분 `Backend/nh-atms-api/atms-web/src/main/java/kr/co/nh/atms`, 프론트 앞부분 `Frontend/nh-atms-web/src`)

**새 화면을 만들 때도 아래 1~6 순서 그대로 합니다.** 공지사항 파일을 복사해서 이름만 바꿔 시작하는 게 가장 빠릅니다.

## 0-1. 어떤 화면을 참고하면 빠른가 — 화면 모양별 견본 고르기

새 화면은 **가장 비슷한 견본 하나를 통째로 복사해서 이름만 바꾸는 것**이 가장 빠릅니다. AS-IS 화면을 보고 아래 표에서 모양을 고르세요.

| 새 화면 모양 (AS-IS 에서 이렇게 생겼으면) | 복사할 견본 | 프론트 파일 (`src/`) | 백엔드 파일 |
|---|---|---|---|
| 조회조건 + 목록, **팝업**으로 등록·수정·상세, 체크해서 여러 건 삭제 | **공지사항** `sample.notice` | `screens/sample/NoticePage.tsx`, `NoticeParts.tsx`, `screens/popup/NoticeEditModal.tsx`, `NoticeViewModal.tsx` | `web/notice/**`, `mapper/notice/NoticeMapper.xml` |
| **[목록] / [등록·수정] 탭** 두 개로 왔다 갔다 (팝업 없이 같은 화면에서 편집), 사용여부 N 으로 삭제 | **기기정보** `sample.mcnInfo` | `screens/sample/McnInfoPage.tsx`, `McnInfoParts.tsx`, `McnInfoColumns.tsx` | `web/mcninfo/**`, `mapper/mcninfo/McnInfoMapper.xml` |

| **탭 여러 개**에 위 모양들이 섞인 관리 화면 (탭마다 조회·등록, 체크박스 표 저장) | **권한관리** `sample.authMgt` | `screens/sample/AuthMgtPage.tsx`(탭 틀), `AuthMgtParts.tsx`(탭 내용), `AuthMgtColumns.tsx`, `screens/popup/AuthUserEditModal.tsx` | `web/authmgt/**`, `mapper/authmgt/AuthMgtMapper.xml` |

## 0-2. 권한 — 부서권한과 개인권한 (2026-11-11)

화면 버튼이 흐려지는지·서버가 403 을 주는지는 **로그인 사용자의 권한코드(`AUTH`)** 로 정해집니다. 권한코드는 `TB_SCR_AUTH` 한 테이블에서 이렇게 고릅니다.

- **부서권한** = `TB_SCR_AUTH.PER_NO = '1'` 인 행. 그 부서·사무소 사람 모두에게 적용됩니다.
  - 내 부서 찾기: `TB_INSA.SAMUSO` → `TB_OFC_RAW.SAMUSO` → 그 행의 `SAMUSO`(부서코드) = `DEPT_CODE`, `ONLINE_CODE`(사무소코드) = `OFC_CODE`.
- **개인권한** = `PER_NO = 내 개인번호` 인 행. **필수가 아닙니다.**
- **개인권한이 있으면 개인권한만** 씁니다(부서권한보다 우선, 섞지 않음). 승인(`APV_STS='Y'`)되고 만료 전인 것만 "있다" 로 칩니다.
- 유효한 개인권한이 없으면 부서권한, 그것도 없으면 권한 없음(버튼이 다 흐림).
- 권한코드 → 메뉴별 조회·등록·수정·삭제·실행은 `TB_SCR_AUTH_MENU`. 셋 다 **권한관리 화면**(탭: 부서권한·개인권한·메뉴 권한)에서 넣습니다.
- 코드 위치: `web/common/auth/CurrentUserLoader.java` `pickEffective`. 자세한 규칙은 [`04_DB_규칙.md`](04_DB_규칙.md) §4-2, 계약 [`07_API_계약.md`](07_API_계약.md) §1·§8.

## 3. 백엔드 — Controller → Service → Mapper

패키지 `kr.co.nh.atms.web.notice` 아래 4개 폴더로 나눕니다.

| 파일 | 핵심 |
|---|---|
| `dto/Notice.java` | 응답 1건. 필드 = 컬럼명 camelCase (`OFC_CODE` → `ofcCode`). 감사 컬럼은 `AuditFields` 상속 |
| `dto/NoticeSearchDto.java` | 조회조건. `PageRequest` 상속(page·size) |
| `dto/NoticeSave.java` 등 | 등록·수정·삭제 요청 본문 |
| `controller/NoticeController.java` | 주소 매핑 + 권한만. `@RequireMenuAuth(screen = "sample.notice", need = Perm.QRY)` 를 메서드마다. 결과는 `ApiResponse.ok(data)` / `ApiResponse.ok(data, "S002")` |
| `service/NoticeService.java` | 업무 규칙: 입력 검사(바이트 길이), 번호 채번(MAX+1), 없으면 `NotFoundException("NTC_001")`. 쓰기 메서드는 `@Transactional` |
| `mapper/NoticeMapper.java` | `@Mapper` 인터페이스. 메서드 이름 = XML 의 `id` |
| `resources/mapper/notice/NoticeMapper.xml` | 실제 SQL. `namespace` = 인터페이스 전체 이름 |

규칙 몇 가지:
- SQL 은 대문자, `#{}` 만 사용(`${}` 금지). 컬럼 → 필드는 `map-underscore-to-camel-case` 로 자동 변환.
- 사용자(작성자)는 `CurrentUser`(로그인한 세션 사용자)에서 가져옵니다.
- 감사 컬럼(`CRT_DTM` 등)은 `AuditInterceptor` 가 채우므로 SQL 에 `#{crtDtm}` 처럼 쓰기만 합니다.
- 오류 문구는 직접 쓰지 않고 응답코드(`VAL_001`, `NTC_001` …)만 던집니다. 문구는 `atms-common/.../api-message/api-messages.tsv`.

> 더 보기: [`03_백엔드_개발가이드.md`](03_백엔드_개발가이드.md)

### 4-1. ① 타입 — `domain/notice.ts`

- 서버 응답(계약 §3)과 **글자 하나까지 같은** TypeScript 타입입니다. 필드 이름 = DB 컬럼 camelCase.

```ts
export type NoticeField = 'ALL' | 'SUBJECT' | 'TEXT' | 'NAME';   // 검색구분

export interface NoticeSearch extends PageParams {   // 조회조건 (page·size 는 PageParams 가 가짐)
  fromDate?: string;  toDate?: string;               // YYYYMMDD 문자열
  ofcCode?: string;   perNo?: string;
  field?: NoticeField; keyword?: string;
}

export interface Notice extends Audit {              // 1건 (Audit = 감사 4컬럼 crtDtm 등)
  no: number; ofcCode: string | null; kanm: string | null;
  subject: string | null; text: string | null;      // 목록에서는 text 가 null
  visit: number | null; name: string | null; perNo: string | null;
  wrtDate: string | null;                            // 'YYYYMMDD'
}

export interface NoticeSave { subject: string; text: string; ofcCode?: string }   // 등록·수정 본문
```

- 날짜는 `Date` 가 아니라 **문자열**(`'20261110'`)입니다. 화면에 보일 때만 `fmtDate()` 로 바꿉니다.
- 값이 없을 수 있는 칸은 `| null` — 화면에서는 `fmt*` 함수가 `'-'` 로 처리해 줍니다.

### 4-2. ② API — `api/endpoints/notice.ts`

```ts
export const noticeApi = {
  list:   (p: NoticeSearch) => api.get<PageResult<Notice>>('/notice', { params: compactParams(p) }),
  get:    (no: number, hit = false) => api.get<Notice>(`/notice/${no}`, { params: hit ? { hit: 'Y' } : undefined }),
  create: (body: NoticeSave) => api.post<Notice>('/notice', body),
  update: (no: number, body: NoticeSave) => api.put<Notice>(`/notice/${no}`, body),
  remove: (nos: number[]) => api.post<NoticeDeleteResult>('/notice/delete', { nos }),
};

export const noticeKeys = {
  all: ['notice'] as const,                                  // 지우기(invalidate)용 뿌리
  list: (p: NoticeSearch) => ['notice', 'list', p] as const,
  detail: (no: number) => ['notice', 'detail', no] as const,
};
```

- **주소는 `/notice` 만** 씁니다. 앞의 `/api/web` 은 `api/http.ts` 가 붙입니다(`VITE_API_BASE`, 기본 `/api/web`).
- `api.get<T>` 는 응답 봉투 `{ success, code, message, data }` 를 벗겨 **`data` 만** 돌려줍니다.
- `compactParams` = 빈 값(`undefined`, `''`) 을 빼서 `?keyword=` 같은 빈 파라미터가 안 가게 합니다.
- **쿼리키** = React Query 캐시의 이름표입니다. `['notice', ...]` 로 시작하는 캐시를 `noticeKeys.all` 한 번으로 전부 "오래됨" 표시할 수 있습니다(→ 목록 자동 다시 읽기).
- 규칙: 화면에서 `axios`/`fetch` 를 직접 쓰지 않습니다. API 호출은 이 파일에만.

### 4-3. ③ 부품 — `screens/sample/NoticeParts.tsx`

화면 본체가 길어지지 않게 "설정 덩어리"를 따로 모은 파일입니다. 4개 구역으로 나뉩니다.

**(1) 조회조건 `useNoticeFields(admin)`** — `SearchForm` 에 넘길 칸 목록 (2026-11-13 실제 화면)

```tsx
export const useNoticeFields = (admin: boolean): SearchField[] =>
  useMemo(() => [
    rangeField({ name: 'period', label: '작성일', maxDays: 366, defaultValue: lastMonth() }),                   // 기간, 최근 1개월
    optionField('scope', '공지 범위', scopeOptions(admin), { allLabel: scopeAllLabel(admin), widthClass: 'normal' }), // 고정 선택지
    ...(admin ? [enabledBy(officeField({ required: false }), 'scope', (v) => v === 'OFC')] : []),             // 관리자만, '사무소 공지' 일 때만 켜짐
    ...keywordTypeFields({ options: FIELD_OPTIONS }),                                                         // 검색구분 + 검색어
  ], [admin]);
```

- **검색필터 안의 칸은 모두 공통 팩토리로 만듭니다(2026-11-13 사용자 결정, 앞으로 만드는 화면도).** 날짜 `rangeField`, 사무소 `officeField`, 고정 선택지 `optionField`, 검색구분+검색어 `keywordTypeFields`, 다른 칸 값에 따라 켜기 `enabledBy` — 직접 `DatePicker`·`Select`·`Input` 이나 `{ type: 'select' }` 를 놓지 않습니다.
- 맞는 부품이 없으면 화면에 만들지 말고 **공통(`components/search`)에 먼저 추가**한 뒤 씁니다(예전 이 화면의 로컬 `KeywordInput` 은 공통 `keywordTypeFields` 로 올렸습니다). 카탈로그 `docs/05_공통모듈_목록.md` §3.

**(2) 조건값 → API 파라미터 `toNoticeParams(v)`** — 폼 값을 서버가 원하는 모양으로 바꿈

```tsx
const { fromDate, toDate } = ymdRange(v.period);     // [Dayjs, Dayjs] → 'YYYYMMDD' 두 개
const scope = allToUndef(v.scope);                   // '' (전체) → 빠짐
return compactParams({ fromDate, toDate, scope, ofcCode: scope === 'OFC' ? allToUndef(v.ofcCode) : undefined,
                       ...keywordTypeOf(v) });       // 검색구분 '전체'·검색어 없음 → field·keyword 둘 다 빠짐
```

- 폼 값(날짜 객체 등)과 서버 파라미터(문자열)는 모양이 다릅니다. **바꾸는 일은 이 함수 한 곳**에서만 합니다.

**(3) 표 컬럼 `noticeColumns(page, size, onOpen)`**

```tsx
[
  indexCol(page, size),                                   // 순번 (페이지 넘어가도 이어짐)
  centerCol('번호', 'no', 70),
  col('제목', 'subject', 360, { render: (v, r) => <Typography.Link onClick={() => onOpen(r)}>{v}</Typography.Link> }),
  col('범위', 'ofcCode', 170, { render: (_, r) => <ScopeTag n={r} />, excel: scopeText }),   // 전체 꼬리표 / 사무소명, 엑셀은 글자
  textCol('작성자', 'name', 100, { align: 'center' }),
  dateCol('작성일', 'wrtDate', 100),                      // 'YYYYMMDD' → 'YYYY-MM-DD' 자동
  countCol('조회수', 'visit', 80),                        // 천 단위 콤마, 오른쪽 정렬
]
```

- 컬럼 함수(`dateCol`, `countCol` …)가 정렬·포맷을 정해 줍니다. 화면마다 포맷을 다시 만들지 않습니다.
- **엑셀은 이 컬럼으로 만듭니다**(`excelColumnsOf(columns)`). 엑셀용 컬럼 목록을 따로 만들지 않습니다. 화면과 다른 글자가 필요하면 `excel:` 옵션.

**(4) 인쇄 조건 `noticePrintConditions()`** — [출력] 했을 때 종이 위쪽에 찍힐 "조회조건 요약".

**(0) 바이트 상한** `SUBJECT_MAX_BYTES = 200`, `TEXT_MAX_BYTES = 4000` — DB 컬럼 크기(VARCHAR2 바이트)와 같게. 입력 팝업이 씁니다.

### 4-4. ④ 화면 본체 — `screens/sample/NoticePage.tsx`

**(1) 상태와 훅 준비**

```tsx
const NoticePage = ({ screenKey }: ScreenProps) => {           // screenKey = 'sample.notice' (레지스트리가 넣어 줌)
  const [form] = Form.useForm();                                // 조회조건 폼
  const qc = useQueryClient();
  const [selected, setSelected] = useState<number[]>([]);       // 체크한 행 번호들
  const [edit, setEdit] = useState<{ open: boolean; no: number | null }>({ open: false, no: null });  // 입력 팝업 (no=null 등록)
  const [viewOpen, setViewOpen] = useState(false);              // 상세 팝업

  const perm = usePermission(screenKey);                        // 버튼 흐림·읽기 전용 안내
  const fields = useNoticeFields(perm.isAdmin);
  const search = usePagedSearch<NoticeSearch, Notice>({ key: noticeKeys.list, fetch: noticeApi.list });
  const invalidate = () => qc.invalidateQueries({ queryKey: noticeKeys.all });
```

- **`usePagedSearch`** 가 이 화면의 핵심입니다. 조회·페이징·로딩 상태를 한 번에 줍니다.

  | 쓰는 값 | 뜻 |
  |---|---|
  | `search.search(조건)` | 조회 시작 (1페이지부터) |
  | `search.rows`, `search.total` | 지금 페이지 목록, 전체 건수 |
  | `search.loading` | 읽는 중 |
  | `search.searched` | 한 번이라도 조회했나 (안 했으면 표에 "조회하세요" 표시) |
  | `search.pagination` | 표 아래 페이지 버튼에 그대로 넘김 |
  | `search.params` | 마지막 조회조건 (인쇄 조건 등에 사용) |
  | `search.refetch()`, `search.reset()` | 같은 조건 다시 읽기, 초기화 |

**(2) 서버에 "쓰는" 요청 = `useMutation`**

```tsx
const view   = useMutation({ mutationFn: (no: number) => noticeApi.get(no, true), onSuccess: invalidate });  // 상세 열기(조회수 +1)
const remove = useMutation({ mutationFn: noticeApi.remove, onSuccess: invalidate });                         // 삭제
```

- 조회는 `useQuery`(=`usePagedSearch` 안), 등록·수정·삭제는 `useMutation` 입니다.
- 상세 열기는 GET 이지만 **조회수를 올리는 요청**이라 `useMutation` 으로 했습니다(화면이 다시 그려질 때 저절로 또 불리지 않게).
- `onSuccess` 에서는 **`invalidate` 만** 합니다 → 목록이 자동으로 다시 읽혀 조회수·삭제 결과가 반영됩니다.
- 성공 문구("3건 삭제되었습니다.")·오류 문구는 `http.ts` 가 **자동으로** 띄웁니다. `message.success`, `try/catch` 를 쓰지 않습니다.

**(3) 버튼 — `ActionBar`**

```tsx
const actions: ActionItem[] = [
  { key: 'search', onClick: () => form.submit(), loading: search.loading },
  { key: 'excel',  onClick: excel, disabled: !search.rows.length },
  { key: 'print',  onClick: () => print(), disabled: !search.searched },
  { key: 'create', onClick: () => setEdit({ open: true, no: null }) },
  { key: 'update', onClick: () => setEdit({ open: true, no: selected[0] }), disabled: selected.length !== 1 },
  { key: 'delete', onClick: onDelete, disabled: !selected.length, loading: remove.isPending, confirm: CMSG.deleteSelected(selected.length) },
];
```

- `key` 만 주면 글자·아이콘·**필요 권한**이 정해져 있습니다(`components/auth/ActionBar.tsx` `ACTION_DEFS`):
  `search·excel·print` = 조회권한, `create` = 등록, `update` = 수정, `delete` = 삭제.
- 권한이 없으면 버튼이 알아서 흐려집니다. 화면에서 `if (권한)` 을 쓰지 않습니다.
- `disabled` 는 "권한은 있지만 지금 누를 수 없음"(예: 1건 선택 안 됨)만 표현합니다.
- `confirm` 을 주면 누를 때 확인창을 띄웁니다. `hotkeys` 를 켜면 단축키도 됩니다.

**(4) 화면 조립 (JSX)** — 위에서 아래로 이 순서가 표준입니다.

```tsx
<PageFrame screenKey={screenKey} extra={<ActionBar screenKey={screenKey} hotkeys actions={actions} />} …>  {/* 제목줄 + 버튼 */}
  <SearchForm form={form} fields={fields} onSearch={onSearch} onReset={search.reset} />                      {/* 조회조건 */}
  <ResultHeader title="공지 목록" total={search.total} selected={selected.length}>                            {/* 건수줄 */}

  <DataGrid<Notice> columns={columns} rows={search.rows} rowKey="no" grade="G1"
                    pagination={search.pagination}

                    onRowDoubleClick={openView} />                                                           {/* 목록 */}
  <NoticeViewModal open={viewOpen} notice={view.data} onEdit={(n) => { setViewOpen(false); setEdit({ open: true, no: n.no }); }} … />
  <NoticeEditModal open={edit.open} no={edit.no} onClose={() => setEdit({ open: false, no: null })} />
  <PrintLayout title="공지사항" conditions={…}> <table>…</table> </PrintLayout>                              {/* [출력] 때만 보임 */}
```

- `onSearch` 는 체크 선택을 비우고 `search.search(toNoticeParams(v))` 를 부릅니다.
- `rowKey="no"` = 행을 구분하는 값(PK). 체크박스 선택값도 이 값입니다.
- 엑셀: `downloadExcel(excelColumnsOf(columns), search.rows, '공지사항')` — 지금 보이는 페이지를 받습니다.

**(5) 사용자 동작별로 일어나는 일**

| 동작 | 화면 코드 | 서버 |
|---|---|---|
| [조회] | `form.submit()` → `onSearch` → `search.search(...)` | `GET /api/web/notice?...` |
| 페이지 이동 | `DataGrid` → `search.pagination` | 같은 GET, page 만 바뀜 |
| 제목 클릭 / 행 더블클릭 | `openView(r)` → 상세 팝업 열고 `view.mutate(no)` | `GET /api/web/notice/{no}?hit=Y` (조회수 +1) → 목록 다시 읽음 |
| [등록] | `setEdit({ open: true, no: null })` | 팝업에서 저장 시 `POST` |
| [수정] (1건 체크) | `setEdit({ open: true, no: selected[0] })` | 팝업이 `GET /{no}` 로 원문 읽고, 저장 시 `PUT` |
| [삭제] (여러 건 체크) | 확인창 → `remove.mutate(selected)` | `POST /api/web/notice/delete` → 목록 다시 읽음 |
| [엑셀] / [출력] | `downloadExcel(...)` / `print()` | 서버 호출 없음 (지금 목록 사용) |

### 4-6. ⑥ 등록/수정 팝업 — `screens/popup/NoticeEditModal.tsx`

3단으로 나뉩니다: **겉(Modal) → 읽기(Body) → 폼(Form)**.

```tsx
// 1) 겉: 닫으면 안쪽을 통째로 버림(destroyOnHidden) → 열 때마다 빈 폼에서 새로 시작
export const NoticeEditModal = ({ open, no, onClose }: Props) => (
  <Modal open={open} onCancel={onClose} width={760} footer={null} destroyOnHidden
         title={<ModalTitle title={no === null ? '공지사항 등록' : '공지사항 수정'} screenKey="popup.noticeEdit" />}>
    <NoticeEditBody no={no} onClose={onClose} />
  </Modal>
);

// 2) 읽기: 수정이면 원문을 읽고(조회수 증가 없음), 다 읽은 뒤에 폼을 그림
const NoticeEditBody = ({ no, onClose }) => {
  const detail = useQuery({ queryKey: noticeKeys.detail(no ?? 0), queryFn: () => noticeApi.get(no!), enabled: no !== null, gcTime: 0 });
  if (no !== null && detail.isError) return <EmptyState text="공지를 불러오지 못했습니다." action={<Button onClick={onClose}>닫기</Button>} />;
  if (no !== null && !detail.data) return <Skeleton active />;          // 읽는 중
  return <NoticeForm target={no === null ? null : detail.data} onClose={onClose} />;
};
```

- **왜 3단?** 폼의 `initialValues` 는 처음 그릴 때 한 번만 들어갑니다. 원문을 다 읽은 **뒤에** 폼을 그려야 값이 제대로 채워집니다.
- `enabled: no !== null` = 등록일 때는 읽지 않음. `gcTime: 0` = 닫으면 캐시를 버려서 다음에 열 때 새로 읽음.

```tsx
// 3) 폼: 검사 규칙은 파일 위쪽 RULES 한 곳에
const RULES = {
  subject: [req('제목'), maxBytes(SUBJECT_MAX_BYTES)],   // 필수 + 200바이트 (한글 = 2바이트로 계산, 서버 DbBytes 와 같은 규칙)
  text:    [req('내용'), maxBytes(TEXT_MAX_BYTES)],
  ofcCode: [],
} satisfies Record<keyof NoticeFormValues, Rule[]>;     // 폼 칸마다 규칙이 빠짐없이 있는지 타입이 검사

const NoticeForm = ({ target, onClose }) => {
  const [form] = Form.useForm<NoticeFormValues>();
  const save = useMutation({
    mutationFn: (body: NoticeSave) => (target ? noticeApi.update(target.no, body) : noticeApi.create(body)),   // 수정/등록 분기
    onSuccess: () => qc.invalidateQueries({ queryKey: noticeKeys.all }),
  });
  const onFinish = (v) => save.mutate(toBody(v), { onSuccess: onClose });   // 검사 통과 → 저장 → 성공하면 닫기

  return (
    <Form form={form} component={false} initialValues={initial} onFinish={onFinish} scrollToFirstError>
      <DetailGrid cols={2} items={[
        { label: '제목', required: true, span: 2, value: formItem('subject', <Input count={byteCount(SUBJECT_MAX_BYTES)} />, RULES.subject) },
        { label: '사무소', value: formItem('ofcCode', <OfficeSelector allowEmpty />, RULES.ofcCode) },
        { label: '작성자', value: <span>{writer.name} ({writer.perNo})</span> },     // 보여 주기만, 서버가 채움
        { label: '내용', required: true, span: 2, value: formItem('text', <Input.TextArea rows={10} count={byteCount(TEXT_MAX_BYTES)} />, RULES.text) },
      ]} />
      <Button onClick={onClose}>닫기</Button>
      <AuthButton screenKey="sample.notice" need={target ? 'upd' : 'reg'} loading={save.isPending} onClick={() => form.submit()}>저장</AuthButton>
    </Form>
  );
};
```

- `formItem(이름, 입력칸, 규칙)` = antd `Form.Item` 을 표준 모양으로 감싼 도우미. 오류 글자는 `utils/rules.ts`·`config/messages.ts` 에서만 옵니다.
- `byteCount(200)` = 입력칸 오른쪽 아래에 "37 / 200" 처럼 **바이트** 카운터.
- `toBody(v)` = 폼 값 → 서버 본문 모양(`NoticeSave`). 제목 앞뒤 공백 제거, 빈 사무소는 빼기.
- 저장 실패(서버 400 등)면 문구는 자동으로 뜨고 **팝업은 열린 채로** 남습니다(`onSuccess: onClose` 라서).
- [저장] 버튼도 `AuthButton` — 등록이면 `reg`, 수정이면 `upd` 권한을 봅니다.

### 4-7. ⑦ 화면 등록 — 메뉴에 연결하기

화면 파일을 만들었다고 메뉴에 바로 나오지 않습니다. **3곳**에 한 줄씩 넣어야 합니다.

| 어디 | 넣는 것 | 공지사항 예 |
|---|---|---|
| `screens/screenIds.ts` | 화면키 (값은 항상 `''`, 화면번호 안 씀) | `'sample.notice': '',` (팝업도: `'popup.noticeEdit': ''`, `'popup.noticeView': ''`) |
| `screens/registry.ts` | 화면키 → 제목·대분류·컴포넌트 | `def('sample.notice', '공지사항', 'sample', '', () => import('./sample/NoticePage')),` |
| DB `TB_SCR_MENU` (`04_DB_규칙.md` §5 SQL 틀) | 메뉴 경로 = 화면키에서 만든 경로 | `SMP002 / 공지사항 / /sample/notice` |

- 화면키 → 경로 규칙: `sample.notice` → `/sample/notice`, `sample.mcnInfo` → `/sample/mcn-info` (점 뒤 camelCase 를 kebab 으로).
- 앱이 뜨면 `GET /api/web/menu/my` 로 메뉴(+권한 5개)를 받고, 메뉴 경로로 레지스트리에서 화면을 찾아 탭으로 엽니다.
  - 메뉴 경로와 레지스트리 경로가 **한 글자라도 다르면** 메뉴를 눌러도 화면이 안 열립니다.
- 권한은 `TB_SCR_AUTH_MENU` 에서 옵니다(권한관리 화면 → 메뉴 권한 탭에서 넣음). 권한 행이 없으면 버튼이 다 흐려집니다.
- 메뉴는 DB 로만 관리합니다(2026-11-12). 프론트에는 메뉴 표가 없고, 메뉴 행은 메뉴관리 화면에서 넣습니다.
- 이 파일들은 **리드가 고치는 공유 파일**입니다. 직접 고치기 어려우면 넣을 줄을 리드에게 그대로 전달하세요.

### 4-9. 하지 말 것 (자주 하는 실수)

| 하지 말 것 | 대신 |
|---|---|

| `.at()`, `replaceAll` 등 (ES2020 아님) | `arr[arr.length - 1]`, `split().join()` |

## 요청 하나 따라가기 — [조회] 버튼을 누르면

1. `NoticePage` 의 [조회] → `search.search(조건)` (`usePagedSearch`)
2. `noticeApi.list(조건)` → `GET /api/web/notice?page=1&size=..&field=SUBJECT&keyword=..` (+ `X-Screen-Key` 헤더)
3. `NoticeController.list` — `@RequireMenuAuth` 가 `TB_SCR_AUTH_MENU` 에서 조회 권한 확인 (없으면 403)
4. `NoticeService.search` — 조건 정리 → `countList` → 0건이 아니면 `selectList`
5. `NoticeMapper.xml` — `TB_NOTICE` 를 `TB_OFC_REG_MGT`(사무소명)와 조인, `NO DESC`, `OFFSET … FETCH NEXT …`
6. `ApiResponse.ok(PageResult)` 로 돌려줌 → `http.ts` 가 봉투를 벗기고 → `DataGrid` 에 표시
