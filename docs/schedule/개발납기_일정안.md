## 5. 작성 기준

- 기간 12/1(화) ~ 3/31(수), 주말·공휴일 제외, 12/31은 근무일
- 개발일수: 난이도 1~2 → 1일, 난이도 3~4 → 2일, 난이도 5~7 → 3일, 난이도 8~10 → 5일 (미정은 담당자 평균 난이도)
- 순서: 264xxx·266xxx 먼저(쉬운 것 먼저) → 나머지 표 순서
- 퍼블 납기 = 개발 시작일 7일 전, 디자인 납기 = 개발 시작일 14일 전 (주말·휴일이면 직전 근무일)
- 260000(11/27)·264000(12/01)은 기존 납기 유지, 중복화면 269300~269304 제외
- 개발 담당자는 사진 원본 그대로(추후 담당자만 수정 예정). 납기 날짜는 이관안 기준으로 산정한 값을 유지: 원 배정대로면 이태성 84일 > 가용 73일이라 8개(266000, 266001, 266002, 266003, 266004, 269311, 269322, 269601)를 김태균, 5개(266107, 269631, 269632, 269633, 269634)를 최성민 일정에 넣어 계산함(표의 노란 칸·'일정 산정 담당자' 열). 원본 담당자 기준으로 보면 이 화면들은 이태성 본인 일정과 기간이 겹칩니다.
- 모든 화면이 3/31 안에 끝납니다(이관안 기준 여유: 최성민 10일, 김태균 7일, 이태성 8일).
- 개발 시작일 = 산정 담당자가 그 화면을 시작하는 날. 소요일 = 시작일~개발납기 평일 수(주말만 제외, 양끝 포함), 실작업일 = 같은 기간에서 공휴일·휴가까지 뺀 날 수. 260000은 난이도 2(1일)로 역산해 시작일 = 납기일.
- 사진 판독 결과 → 원본과 대조 필요 (266107 원 담당자 = 이태성으로 판독)
